# F10.3 Markdown Renderer Implementation Plan

**Goal:** Render vendor markdown in the desktop app from one safe model: F10.3a parses
untrusted vendor output into an immutable document (`ui/internal/markdown`, no Gio), F10.3b
draws that document with Gio (DA-03). The split is Q-43; one PR each, F10.3b cut from `main`
after F10.3a merges.

**Design:** `desktop-app` DA-03 (own renderer on goldmark, never `gioui.org/x/markdown`), DA-E03
(golden whitespace behaviour), `§9` (layout p95 ≤ 8 ms); `transcript` TR-07 (CommonMark plus the
GFM table, strikethrough and task-list extensions; no raw HTML rendering; hosts shown with
links; images from URLs never fetched), tabs expanded to spaces before drawing.

## F10.3a — the model layer (this PR)

`Parse(src string) *Doc` builds an immutable document of blocks and style-tagged spans.
The package imports `gioui.org` nowhere; nothing in it draws.

### Model

- Blocks: paragraph, heading (levels 1–6), thematic break, fenced and indented code block,
  blockquote, ordered and unordered lists (nested, tight or loose), task-list items
  (read-only checked state), GFM tables with per-column alignment, hard line breaks inside
  paragraphs.
- Spans: plain, bold, italic, bold-italic, strikethrough, inline code, link, image, hard
  break marker. Spans carry their source text verbatim so the whitespace around inline code
  and bold, and between adjacent spans, is exactly the source's (DA-E03).
- Tabs everywhere (code blocks and text) expand to spaces on a 4-column tab stop before the
  text enters a span, so no tab ever reaches a shaper in F10.3b.
- Code blocks keep their interior whitespace line for line; fenced blocks with a language
  chroma knows are tokenized into role-tagged spans (data only — the model holds no colors).

### Syntax roles

`keyword, operator, variable, function, type, definition, string, number, comment, meta,
invalid, plain` — chroma token categories mapped once in `highlight.go`; the analyser
(`Analyse`) is never called, so an unknown or missing language stays plain by decision, not
detection. The role names deliberately match `theme.SyntaxRole`'s string values, but the type
is defined here because `ui/internal/theme` imports Gio and this package must not. F10.3b maps
model roles onto theme roles one-to-one.

Decisions recorded here:

- **definition is never emitted.** No chroma token type separates a declaration from a use;
  mapping `Name.Function` to `function` (as the item specifies) leaves nothing that can mean
  "name at its declaration". The role stays in the set so the theme and the mapping in F10.3b
  keep a place for it.
- **Keyword.Constant maps to number** (true/false/nil/null read as constants), except inside
  `Comment.Preproc`, which maps to meta as specified.

### Safety (untrusted vendor output)

- Raw HTML, block and inline, becomes literal text spans; nothing is ever interpreted.
- Links keep their text, a normalized URL, the host, and `Openable`. Only `http`, `https` and
  `mailto` are openable; `javascript:`, `file:`, `data:`, `vbscript:`, relative paths and any
  other scheme stay plain text.
- Control characters, bidi overrides (U+202A–U+202E, U+2066–U+2069) and zero-width characters
  are stripped from text and URLs, so displayed text cannot forge a host.
- IDN hosts keep the punycode form beside the display form. Punycode conversion (RFC 3492) is
  implemented in-package (`idna.go`): `golang.org/x/net/idna` would be a new module for two
  functions, and x/net is only an indirect dependency today.
- Images are never fetched. The model keeps the alt text and the destination host, nothing
  else; F10.3b renders the alt text.

### Resource limits (named constants)

| Constant | Value | Behaviour when exceeded |
| --- | --- | --- |
| `maxSourceBytes` | 1 MiB | the source is cut and `Doc.Truncated` is set |
| `maxNestingDepth` | 64 | deeper blocks are dropped, `Truncated` set |
| `maxTableColumns` | 64 | extra columns dropped, `Truncated` set |
| `maxTableCells` | 4096 | extra rows/columns dropped, `Truncated` set |
| `maxHighlightBytes` | 64 KiB | the code block stays plain |
| `maxHighlightLines` | 2000 | the code block stays plain |

A lexer error leaves the block plain; parsing never panics and never allocates in proportion
to anything but the (already capped) input.

### Tests

Golden model dumps in `testdata/` — one file per case, updated with `-update` — covering the
DA-E03 model cases: whitespace around code and bold, nested lists, task lists, aligned tables,
tabbed code, highlighted Go and TypeScript, unknown language, links (blocked schemes, bidi,
IDN), raw HTML, images. Named tests pin the guarantees the goldens only show; `FuzzParse`
checks no-panic and limit respect on arbitrary input.

Fuzz note: the fuzz-short gate enumerates the core module only, and the ui workflow runs build,
vet, lint and tests without a fuzz step. `FuzzParse` therefore runs its seed corpus under the
ui test job (both OSes) and is not covered by a short-fuzz gate; per the item, no workflow is
changed for it.

### Dependencies

`github.com/yuin/goldmark` (MIT) and `github.com/alecthomas/chroma/v2` (MIT) enter `ui/go.mod`
only, with rows in `docs/dependencies.md` (a gate file: this PR needs `gate-change-approved`).

## F10.3b — the layout layer (next PR, `feat/f10.3b-markdown-layout`)

Cut from `main` after F10.3a merges. Scope from the item:

1. `Layout(gtx, theme, doc, *State)` drawing the model: bold via `font.Bold`, code and inline
   code in JetBrains Mono, links underlined dotted with a small ↗ glyph.
2. The link popover (hover or keyboard focus, `op.Defer` above the link): generic link icon —
   no favicon, no network — full URL middle-truncated with the host always whole, an open and a
   copy button. The popover sticks while the pointer travels from link to popover and hides
   when it leaves both. Clicking the link pins the popover instead of opening it; the open
   button emits `OpenLink(url)` to the caller, which decides. Non-openable links render as
   plain text, no popover. Owner decision 2026-11-10, deviating from TR-07's letter: the host
   is shown in the popover on hover/focus, not inline beside the link.
3. The syntax palette from the F10.2c roles for light and dark, each role at weight 400 unless
   the mapping says otherwise (comment italic), every role ≥ 4.5:1 on the code-block surface
   of its mode, with a contrast test for every role in both modes.
4. Code blocks on their own rounded surface, horizontally scrolling, never wrapping inside a
   token.
5. `ui/cmd/mdpreview` (dev only, not packaged, never imported by fugue-app): scrollable
   preview of one `.md` file with a light/dark toggle; `OpenLink` handled through `xdg-open`
   (Linux) and `open` (macOS) with the URL as a single argv and http/https/mailto only;
   `ui/internal/markdown/testdata/preview.md` gathers the DA-E03 cases including Go and
   TypeScript code; run instructions in `ui/README.md`.
6. Tests: headless layout (fonts, no tabs to the shaper, popover hover/focus behaviour, copy
   and open events, blocked links), and the layout benchmark of a 20 KB document with
   highlighted code, measured before `t.Parallel` as #93 did, against the p95 ≤ 8 ms budget.
