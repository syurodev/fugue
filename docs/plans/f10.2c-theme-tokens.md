# F10.2c Theme Tokens Implementation Plan

**Goal:** One shared token layer in `ui/internal/theme` for every screen (F10.3b markdown, F10.4 transcript, F10.5 dialogs), with exactly two modes: light and dark.

**Architecture:** Two token tiers per mode. Chrome is the neutral, monochrome tier every widget uses (backgrounds, text levels, borders, the action color); the palette is the eight-hue tier for syntax, status and accents. Chrome never uses a hue directly. Status, link and syntax-role colors are derived once from the palette so no screen picks its own color. The tokens are constants in code — one table per mode — and each hue is tuned for lightness only until it reaches a WCAG contrast of at least 4.5:1 on every chrome background of its mode.

**Design:** desktop-app DA-08 (two modes, no palette families); roadmap F10.2c.

## Constraints

- Exactly two modes: light and dark. No palette families, no user palette choice (that is F10.5 at the earliest).
- Chrome never references a hue. Status and syntax roles are defined once, in this package; screens never set colors of their own.
- Contrast: every text-level token (fg, muted) and every palette hue reaches at least 4.5:1 on app bg, canvas, surface base, surface raised and surface tinted of its own mode. FgSubtle (and comment/meta/`FgSubtle`-derived roles) reach at least 3:1: they color de-emphasized text and comments that sit next to identifiable content, the AA large-text/graphics threshold; pushing them to 4.5:1 erases the visual hierarchy between muted and subtle text on both modes.
- `Material()` returns a `*material.Theme` seeded from the tokens (Fg, Bg, ContrastBg, ContrastFg, Shaper) so stock Gio widgets keep working.
- No writable globals (`gochecknoglobals` is on): token tables are built by functions, not package variables.
- The app follows the OS light/dark preference only if Gio v0.10.3 exposes it through `gioui.org/app`. Checked: it does not — no dark-mode or color-scheme API exists in v0.10.3 (`app.Window`, `app.Option`, `io/system`). So the app starts light, Ctrl+D toggles as today, and the plan records this gap; no DBus, no cgo, no `defaults read` in this item. When Gio grows the API, `Light`/`Dark` already build both modes, so wiring is a one-line change at startup.
- The mode choice is not persisted; Settings is F10.5.
- No lines in `ui/internal/appwin` may construct `color.NRGBA` after this item; all colors come from `ui/internal/theme`. A source-scan test enforces it without touching `internal/arch` (gate file).
- The syntax role names (keyword, string, number, type, function, definition, variable, operator, comment, meta, invalid) are defined here as a shared type because the markdown package (F10.3a) is not merged yet; F10.3a/F10.3b import them from here rather than redefining them.
- Size ceiling: about 1,000 gross non-test lines for the item; expected about 300–450.

## Color tables

Tuned by binary-searching HSL lightness at fixed hue and saturation until the WCAG 2.x contrast ratio passes 4.5:1 on the worst chrome background of the mode (white surfaces in light mode, app bg in dark mode). The tables below are the source of truth; the contrast test recomputes every pair.

- Light chrome: app `#F2F2F0`, canvas `#FFFFFF`, surface base `#FFFFFF`, surface raised `#E9E9EB`, surface tinted `#E4E4E8`; fg `#1C1D20`, fg muted `#52535A`, fg subtle `#6E6F77` (≥3:1, see above), icon muted `#52535A`; hairline border `#C9C9CE`, focus border `#1C1D20`; action `#1C1D20` with fg `#FFFFFF`, hover `#2E3036`, pressed `#0A0B0C`.
- Dark chrome: app `#14161A`, canvas `#1A1D22`, surface base `#1F2228`, surface raised `#272B33`, surface tinted `#23272E`; fg `#F0F0F2`, fg muted `#A8AAB2`, fg subtle `#85878F` (≥3:1), icon muted `#A8AAB2`; hairline border `#3B3F48`, focus border `#F0F0F2`; action `#F0F0F2` with fg `#14161A` (light bg, dark fg — the inversion the item asks for), hover `#D6D6DA`, pressed `#FFFFFF`.
- Light hues (lightness limited by 4.5:1 on white): red `#B43D34`, orange `#8D5B29`, yellow `#7A6423`, green `#227537`, teal `#217267`, blue `#2A5AE1`, violet `#7B3FE4`, pink `#B33474`. Light-mode yellow and orange read olive/brown — unavoidable at 4.5:1 on white; dark-mode yellow `#AF8E29` has the same constraint.
- Dark hues: red `#DC736B`, orange `#CE7F30`, yellow `#AF8E29`, green `#3FA558`, teal `#3DA194`, blue `#728FDE`, violet `#A084D0`, pink `#CB77A1`.
- Derived: info→blue, success→green, warning→orange, danger→red, link→blue; keyword→violet, string→green, number→orange, type→yellow, function→blue, definition and variable→fg, operator→fg muted, comment→fg subtle (italic), meta→fg subtle, invalid→danger; every syntax style defaults to weight 400.

## Tasks

1. **Token package.** `ui/internal/theme`: `Chrome` and `Palette` token sets, derived status/link and syntax-role colors, the `SyntaxRole` type shared with F10.3a/b, `Light(shaper)`/`Dark(shaper)` constructors and `Theme.Material()`.
2. **Contrast and mapping tests.** A WCAG ratio function in the test (no dependency): every hue and fg token against every chrome background of both modes; derived-role equality (danger == red, keyword == violet, …) in both modes; `Material()` mirrors Fg/Bg/ContrastBg/ContrastFg/Shaper.
3. **appwin conversion.** `themes`/`rgb` in `window.go` are replaced by `theme.Light`/`theme.Dark`; the status bar colors connected states with success/warning/danger tokens instead of the plain fg where appropriate; the source-scan test keeps `color.NRGBA` out of `appwin`.
4. **Delivery.** ui gates (`go vet`, pinned golangci-lint, `go test -race -shuffle=on ./...`), core `go tool task check`, CI on ubuntu and macOS, evidence and §8 Log recorded, F10.2c In review with the PR link.

## Review focus

- A hue that fails 4.5:1 on some surface (raised and tinted are easy to miss).
- A screen sneaking its own color: the source-scan test must fail on any `color.NRGBA` literal in `appwin`.
- `Material()` drifting from the tokens so stock widgets show different colors.
- Syntax role names not matching what the markdown renderer (F10.3a) will call them.
