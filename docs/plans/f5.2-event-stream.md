# F5.2 — Host API event stream implementation plan

Status: **working plan**, written 2026-11-07 against `main` at `48dc58c` (F5.1c merged in PR
#70). One branch, `feat/f5.2-event-stream`, one PR (or two, see § Split).

**Goal:** a server-streaming `Subscribe(topic, cursor?)` RPC over the private socket, backed by
an event hub in `internal/app` with two topic kinds — durable (catch-up from a store, port
implemented by F9.3/F9.4) and ephemeral (bounded in-memory buffer, deltas coalesced or
dropped) — with snapshot-then-stream consistency (no gap), per-topic monotonic sequences,
cursors of topic + host incarnation + sequence, never-blocking publishing, `resync_required`
on overflow, default-deny topic authorization, clean stream end on drain, and one real
ephemeral `host` topic (lease counts and draining) so the end-to-end path runs over the socket.

**Spec:** base-doc `host-api §6` (event stream, two topic kinds, backpressure, `resync_required`),
`host-api §7` (principals — the `session` principal exists in the authorization model but is
never allowed by default), `host-api §8` (versioning — all changes additive in
`fugue.host.v1`), `host-api §10` HA-E03 (catch-up evidence); `event-storage-recovery §9` last
paragraph (client delivery: consistent view plus sequence, catch-up without a
snapshot/subscribe gap, latest-for-key deltas may coalesce, durable control events are never lost to UI
backpressure, a slow UI never holds a transaction or blocks cancellation); `transcript §5–6`
(the topics later items publish on this stream: durable `transcript:<session>`, ephemeral
`transcript-delta:<session>` coalesced at 30/s).

**Where things live (ADR 0001/0002 layering):**

- `internal/app` (layer 4, row already present, no ADR change): the event hub. It composes
  topics, sequences, cursors, authorization and backpressure; domain services of later items
  publish through it. New file `internal/app/eventhub.go` (+ `eventtopic.go` if needed for the
  500-line gate), additions to `errors.go` and `host.go`.
- `internal/hostapi` (layer 5): the `Subscribe` Connect handler mapping proto to domain types,
  plus drain integration. `app.Backend` gains `Subscribe`; `hostapi` imports `app` (declared
  edge), never the reverse.
- `proto/fugue/host/v1/event.proto` (new), `host.proto` (additive rpc), generated code
  committed (`task generate`).

No new package, no new import edge, no new third-party module, no new public error code:
denied subscription is `permission_denied`, subscribing while draining is `unavailable`, and
`resync_required` is a stream end message, not an error. `docs/error-codes.md` is unchanged
(checked by `TestErrorCodesPublished`, which only requires that declared codes are published).

## Proto contract (additive; `buf breaking` against main passes)

`event.proto` (new): `EventCursor{topic, incarnation_id, sequence}`,
`SubscribeRequest{topic, cursor?}`, `HostEvent{sequence, type, payload}`,
`SnapshotEvent{sequence, state, incarnation_id}`, `StreamEnd{resync_required}`,
`SubscribeResponse{oneof kind: snapshot | event | end}`. `host.proto` (modified):
`rpc Subscribe(SubscribeRequest) returns (stream SubscribeResponse);` added to `HostService`.
`payload`/`state` are opaque, topic-specific encodings; typed messages come with the module
services that own the topics (F5.3, F9.9).

## Interfaces

```go
// internal/app (eventhub.go)
type EventSeq = uint64

// An event with LatestForKey carries the complete latest state for its Key —
// never an increment, never a piece. That is what makes coalescing and
// dropping safe: the next event for the key, or a resync, restores the state.
type Event struct {
    Seq          EventSeq
    Type         string
    Key          string // coalescing key; required for a latest-for-key event
    Payload      []byte
    LatestForKey bool   // full latest state for Key; coalescable and droppable
}

type EventCursor struct{ Topic, Incarnation string; Sequence EventSeq }

// DurableTopic is the port a committed-state owner implements (F9.3/F9.4). The
// hub defines it; a fake implements it here. Snapshot and Since must be atomic
// against the store's own commits so (state, seq) is consistent.
type DurableTopic interface {
    Snapshot(ctx context.Context) (state []byte, seq EventSeq, err error)
    Since(ctx context.Context, seq EventSeq) ([]Event, error) // ErrEventSeqTooOld when purged
}

// A durable topic's owner publishes after its commit, in commit order. An
// out-of-order publish is an anomaly: the event is not fanned out, the
// anomaly is logged without the payload, and the topic's live subscribers are
// ended with resync_required so they catch up through Since.

type EventHub struct{ /* incarnation, topics, authorizer, counters */ }
func NewEventHub(incarnationID string) *EventHub
func (h *EventHub) RegisterDurable(name string, src DurableTopic) error
func (h *EventHub) RegisterEphemeral(name string, snapshot func(ctx context.Context) ([]byte, error), bufferCap int) error
// Publish never blocks and holds no core transaction. The sequence is the
// topic owner's concern: an ephemeral topic gets the next sequence from the
// hub, while a durable topic's owner sets ev.Seq from its committed log —
// that sequence survives a restart, and a hub counter would not.
func (h *EventHub) Publish(name string, ev Event) (Event, error)
func (h *EventHub) Subscribe(ctx context.Context, p SubscribeParams) (*Subscription, error)
func (h *EventHub) SetAuthorizer(func(principal, topic string) bool) // nil restores the default
func (h *EventHub) EndStreams() // drain: end every subscription cleanly, refuse new ones
func (h *EventHub) Dropped() uint64  // latest-for-key deltas dropped under queue pressure
func (h *EventHub) Coalesced() uint64

type SubscribeParams struct{ Principal, Topic string; Cursor *EventCursor }

type Subscription struct{ /* pre-taken snapshot, pending catch-up, live queue */ }
func (s *Subscription) Snapshot() (state []byte, seq EventSeq, ok bool) // ok=false on catch-up
func (s *Subscription) Next(ctx context.Context) (Event, bool)          // false: stream ended
func (s *Subscription) ResyncRequired() bool                            // end reason
func (s *Subscription) Close()                                          // idempotent unsubscribe
```

Wiring: `app.StartHost` creates the hub from the incarnation, registers the ephemeral `host`
topic (snapshot = the runtime's counts + draining flag as JSON) and passes it to the runtime,
which publishes `host.clients` and `host.draining` after releasing the runtime mutex
(publishing never holds it). `app.Backend` gains
`Subscribe(ctx, SubscribeParams) (*Subscription, error)`; the runtime delegates to the hub.
`app.StreamEnder` (`EndStreams()`) is an optional interface the server asserts at drain.

## Decisions this plan makes

1. **No-gap protocol.** `Subscribe` registers the subscriber's queue under the hub mutex
   *first*, then takes the snapshot. For an ephemeral topic the sequence is read under the
   hub lock and the state is read outside it — the snapshot call holds no lock, so a slow
   snapshot never blocks `Publish`, and there is no gap: every event published after the
   sequence read is queued and delivered after the snapshot. The state read may also include
   events that race it; those arrive again from the queue, so topic state payloads are
   idempotent to re-apply. For a durable topic the store's own atomic snapshot answers. The
   handler sends the snapshot, then delivers queued events with `seq > snapshot seq`; a
   monotone `lastSent` per subscription deduplicates catch-up overlap. Pinned by tests that
   publish concurrently with Subscribe — including one whose snapshot blocks mid-read.
2. **Backpressure and the latest-for-key contract.** `Publish` never blocks: fan-out appends
   are non-blocking. Each subscriber's queue is bounded. On a full queue: a latest-for-key
   delta coalesces into the queue tail (same key) or is dropped (counter); anything else
   marks the subscriber overflown and its stream ends with `resync_required` — control
   events are never dropped silently, for either topic kind. Dropping is safe only because a
   latest-for-key event carries the complete latest state for its key, never an increment
   (transcript §5): topics whose deltas are pieces must not set the flag. The per-topic
   ephemeral ring evicts exactly the oldest entry when full, so it stays a suffix of the
   published sequence and `ringCovers`'s first-entry check stays sound: a cursor below the
   ring's oldest gets a snapshot, never a partial catch-up.
3. **Cursor semantics.** Cursor = topic + host incarnation + sequence. Ephemeral: a missing
   cursor, an incarnation mismatch, a future sequence, or a sequence below the ring's oldest
   gets a fresh snapshot. Durable: the cursor survives a host restart — the store decides;
   `Since` answers catch-up or `ErrEventSeqTooOld` → snapshot. `SnapshotEvent` carries
   `incarnation_id`, so a client builds its next cursor without calling `HostStatus`.
4. **Authorization (default deny).** The default authorizer allows exactly: the topic is
   registered **and** the principal is a local Host API client kind (`tui`, `cli`, `app`,
   `app-background`). Unknown topics, unknown principals and the `session` principal are
   denied (`permission_denied`) — the `session` principal of host-api §7 is named in the model
   and never allowed by default; token authentication itself is not built here. `Subscribe`
   before `Hello` is rejected (`permission_denied`, existing `ErrHelloFirst`).
5. **Keepalive/idle policy for streams** (deferred to here by F5.1): the F5.1 no-timeout
   decision stands — no `ReadTimeout`/`ReadHeaderTimeout`/`IdleTimeout`, no application-level
   keepalive frames in F5.2. Stream liveness *is* connection liveness: a closed or dead
   client's connection closes the stream (request-context cancellation plus the existing
   connection close hook), the subscriber is unsubscribed, and its queue is bounded, so a
   stalled reader costs bounded memory, never unbounded growth. Clients detect a dead host by
   socket close (existing behavior) and resynchronize with the cursor. HTTP/2 PING keepalive
   can be revisited additively if the F10.2 client needs it.
6. **Durable publish order.** A durable topic's owner publishes after its commit, in commit
   order. A publish at or below the topic's last published sequence is an anomaly: the event
   is not fanned out, the anomaly is logged without the payload, and the topic's live
   subscribers are ended with `resync_required` so they catch up through `Since`.
7. **Drain.** `Server.Drain` ends every open stream (hub `EndStreams`) before shutting the
   HTTP server down; each handler sends `StreamEnd{resync_required: false}` and returns, so
   the in-flight wait and `Shutdown` finish promptly. Subscribing after the drain started is
   rejected by the existing admission gate (503) and by the hub (`unavailable`).
8. **The `host` topic** (ephemeral, registered by this item — the only stage-A topic here;
   later items register theirs): events `host.clients` (lease counts per kind) and
   `host.draining` (drain reason), payload JSON, snapshot = current counts. Control events
   (not droppable).

## Tests

`internal/app` (fake clock where time matters, goleak, -race -shuffle=on; no sleeps —
channels and the fake clock only):

- `TestSubscribeWithoutCursorGetsSnapshotThenEvents` — missing cursor: snapshot then events.
- `TestEphemeralCursorCatchUpFromTheBuffer` — cursor within the ring: catch-up, no snapshot.
- `TestEphemeralCursorOlderThanBufferGetsSnapshot` (HA-E03).
- `TestEphemeralCursorIncarnationMismatchGetsSnapshot` (HA-E03).
- `TestNoGapBetweenSnapshotAndStreamUnderConcurrentPublish` — publisher goroutine hammers the
  topic while `Subscribe` runs; every sequence appears exactly once across snapshot + stream.
- `TestPublishNeverBlocksOnASlowSubscriber` — stalled reader, bounded queue, publish loop of
  deltas returns (channel-observed, no sleeps); deltas coalesced/dropped, counters move.
- `TestControlOverflowEndsWithResync` — a subscriber that cannot keep up with control events
  ends with `resync_required`; no control event is dropped silently.
- `TestEphemeralRingCatchUpBoundariesWithInterleavedKeys` — a ring pushed past capacity with
  interleaved keys: a cursor at the ring's edge catches up to exactly the retained events, a
  cursor just below it gets a snapshot.
- `TestDurableOutOfOrderPublishResyncsSubscribers` — a durable publish below the last
  published sequence is not fanned out; the live subscriber ends with `resync_required` and
  catch-up reads the committed log.
- `TestSlowSnapshotDoesNotBlockPublishAndKeepsNoGap` — a snapshot blocked mid-read does not
  block `Publish`; the queued events are delivered after the snapshot with no gap.
- `TestUnknownTopicIsDenied`, `TestUnknownPrincipalIsDenied`, `TestSessionPrincipalIsDenied`.
- `TestDurableCursorReconnectsAtTheRightSequence`, `TestDurableTooOldCursorGetsSnapshot`,
  `TestDurableSlowClientGetsResyncAndThePublisherNeverBlocks`,
  `TestDurableCursorSurvivesRestart` (F5.2b scope).

`internal/hostapi` (real socket, generated Connect client, as in the F5.1 tests):
