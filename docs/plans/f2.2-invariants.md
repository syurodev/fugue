# F2.2 — Kernel invariants and property tests

Status: implemented on the F2.2 branch, under validation; not yet merged.
Depends on F2.1 (PRs #33 and #34 merged). Design authority: state-machine §3,
quality-gates §6, and ADR 0001. Q-06 is approved for rapid v1.3.0 in tests only.

## Deliverables

1. A pure checker for SM-01 through SM-12. Report stable invariant IDs and structural
   references only; never include protected payloads or contents in diagnostics.
2. Positive and deliberately violating cases for every invariant, evaluated at complete
   transaction-batch boundaries. Intermediate event prefixes are not committed states.
3. Rapid state-machine properties generating bounded command sequences through the existing
   Decide/Evolve path. Include valid progression, invalid transitions, stale ownership and
   executor fences, duplicate observations, and conflicting completions.
4. Verify invariants after every accepted batch. Rejection/no-op leaves the input state
   unchanged; replaying the complete accepted history twice yields equivalent state.
5. Preserve the deterministic 22-event Trace A regression, pure replay without dispatch,
   and ownership of permission/process evidence in the external services.

## Evidence mapping

| Invariants | Checks and required evidence |
| --- | --- |
| SM-01 | At most one active model/tool attempt; approval and timers do not occupy workers. |
| SM-02–03 | Exact approval/dependency pairing, generation and request/args references; waiting projection preserves concurrent reasons. |
| SM-04 | Current-step model/tool frontier agrees with derived phase. |
| SM-05–06 | Finish requires terminal control dispositions, no known active workers, closed/accounted time windows, and execution-inert dependencies/timers; unresolved unknown takes precedence over cancelling. |
| SM-07 | A new model dispatch follows closure and canonical ordered results of the previous step. |
| SM-08–09 | Retry preserves the invocation and old attempt evidence; completion matches admission/incarnation/executor fences; duplicate results cannot become canonical twice. |
| SM-10 | Dispatch cannot pass unresolved blockers or terminal stop intent; current gateway evidence remains required. |
| SM-11 | Unknown exposure remains represented after control closure; finish is never process-stop proof or resource-release authority. |
| SM-12 | Rebuilding an undispatched queued run preserves Queued and performs no effect. |

First audit which facts are retained by the current State/Evolve implementation. Where a
checker requires history (for example retry identity, dispatch-time fences, or prior-step
closure), check transition/batch evidence rather than pretending the final state proves it.
Retain existing event facts in projections where needed. Do not invent owner authority,
process-stop proof, accounting coverage, or implement F3 command handlers as part of F2.2.
Record a design question if any invariant requires a semantic decision beyond the design.

## Validation and delivery

Run task check, including architecture, kernelpure, race/shuffle tests, coverage and mutation.
Require kernel coverage ≥90% and mutation ≥85%, with no suppression or lowered baselines.
Review generator bias and shrinking, so generated tests exercise both meaningful valid
transitions and rejected commands. Retain failing seeds/cases as reproducible regressions.

Use one F2.2 branch and PR from main. Update the roadmap with actual evidence names and PR
link; mark Done only after merge and green CI. Check the diff budget before PR creation;
if a split is needed, propose the concrete split for approval instead of silently expanding it.

## Implementation contract

- `CheckInvariants` checks a committed snapshot; it cannot certify history.
- `CheckBatch` validates event order, the complete resulting snapshot and host-bound
  completion/dispatch metadata. Its preceding state must come from already checked batches.
- `CheckHistory` checks all batches from the empty state. Retain each batch's host metadata
  when auditing history: executor/owner evidence cannot be inferred from event names.
- Retained facts include pending/last approval and owner resolution, dispatch incarnation,
  model failure/interruption partial refs, time-window close coverage and tool exposure.
- Receipt references are observations from owning services. These checkers do not verify
  receipts cryptographically, prove process exit, release writers, dispatch work or grant
  permission. F3 and owner integration tests must still cover their full service paths.
- Rapid generates bounded mixed valid, stale, duplicate and conflicting observations through
  Decide; only accepted batches enter history. Rejections leave state unchanged. Tests also
  exercise retry, approval and unknown-close event fixtures without adding F3 handlers.
- The user approved one F2.2 PR for the roughly 1,600-line implementation and tests on
  2026-11-02. The normal diff guideline remains unchanged for other work.
