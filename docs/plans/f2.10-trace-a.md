# F2.10 — End-to-end slice (Trace A) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

Status: approved plan, written 2026-11-06 against `main` at `1ac661f` (F2.6a merged in
PR #56). Starts only after **F2.6b and F2.6c are merged**: the user kept F2.10's roadmap
dependency on the whole of F2.6 (2026-11-06), although Trace A has no timer.

**Goal:** One run goes start → model → tool → model → finish through the real coordinator,
execution store, faux provider and `pure_read` tool, producing exactly the 22 events of Trace A
in the 12 transactions of `event-catalog` §7; replaying the stored run makes zero model and
tool calls.

**Architecture:** `internal/app` composes the pieces. A **driver** turns each committed state
into the next mechanical command (dispatch the planned model attempt, start a tool check,
dispatch a ready tool) — it decides nothing the kernel decides. A **model executor** and a
**tool executor** implement `coordinator.Executor` over `faux.Provider` and
`pure_read.Tool`, reporting observations with their payloads. Small **host records** give the
kernel the evidence refs it requires (queue decision, model authorization, tool gate result,
context) as IDs of real sealed payloads. The coordinator gains one hook so the driver hears
about every commit.

**Tech Stack:** Go stdlib, `internal/{app,coordinator,execstore,kernel,modeladapter/faux,
tools/pure_read,storage,vault,codec}`, `go-cmp`, `goleak`. No new module.

**Spec:** base-doc `content/projects/dev-kit/core-harness/` at `0ec4431`: `event-catalog` §7
(Trace A, the evidence); `architecture` §3 (one-step protocol, no UI-triggered execution);
`event-storage-recovery` §2 (dispatch protocol), §4 (origin), §6 (transcript projection);
`model-adapter` §2–3 (stream events, stop reasons); `tool-system` §2 (Prepare/Execute).
Repository authority: roadmap F2.10, ADR 0001, `docs/quality-gates.md`, the F2.6, F2.7, F2.8
and F2.9 plans as merged.

## Global Constraints

- **Every ref the kernel requires is the ID of a real sealed payload** written in the same
  transaction as the event that names it (`coordinator.Payload`, F2.6b). Never a constant,
  a generated placeholder, or a ref with nothing behind it.
- Origins: the run's `AcceptRun` is `user` (the test plays the authenticated host layer);
  commands the driver submits are `session`; worker observations are `worker` (set by the
  coordinator). Nothing reads a command's own `Origin`.
- The driver never decides continuation, budgets or outcomes; the kernel (F2.9) does.
- No goroutine outside `supervise.Go`; no `time.Sleep`; tests wait on channels and use the
  fake clock; `goleak` in every `TestMain`.
- Coverage of `internal/app` ≥ 80 %, `internal/coordinator` stays ≥ 90 %; files ≤ 500 lines.
- **ADR change:** `internal/app`'s "May import" lacks `internal/tools/pure_read`. Add
  `internal/tools/...` to that row in `docs/adr/0001-package-layout.md` in this PR; the owner
  approves it (CODEOWNERS covers `docs/adr/**`; the PR needs `gate-change-approved`).
- PR budget ~600 changed non-test lines. If it will be exceeded, stop and ask; the split point
  is Tasks 1–3 (pieces) vs Tasks 4–5 (driver and evidence).

## Scope decisions made by this plan

1. **Commit hook.** `coordinator.Config` gains `OnCommitted func(runID string, state *kernel.State)`,
   called by the actor after every commit it applies (submission, observation, admission,
   dispatch, read-back). It must not block and must not call back into the session
   synchronously; the driver enqueues and acts from its own goroutine. `state` is the
   actor's post-commit snapshot; `Evolve` returns fresh state, so it is read-only, never
   mutated by the actor afterwards. A lost notification is recoverable: the driver can always
   recompute from `Store.LoadRun` (architecture §3).
2. **Next command is a pure function of state** (`nextCommand`, Task 4): model attempt
   `Planned` and no active attempt → `PrepareDispatch(model)`; frontier tool `Planned` →
   `PrepareDispatch(tool)` (starts the check); tool `Checking` → run the gate and submit
   `ObserveToolCheck`; tool `Ready` → `PrepareDispatch(tool)` (dispatch); run finished or
   waiting → nothing.
3. **Context.** The context engine is F4.5. For F2.10 the context of a step is the canonical
   transcript material so far (input, selected responses, tool results) serialized with
   `codec` as one `context` payload; `ModelRequestPlanned.ContextRef` names it, and the model
   executor builds `modeladapter.Request` from it. No summarization, pruning or layering.
4. **Host records.** `queue_decision` (policy `admit_when_idle`, version), `model_authorization`
   (model ref, provider `faux`, no account), `tool_gate` (tool name, descriptor version,
   pure-read class, "no approval required") are small canonical records sealed as payloads;
   their IDs fill `QueueDecisionRef`, `DispatchAuthorizationRef` and `GateObservation`.
5. **Usage.** `BudgetObserved.TokensUsed = (Input − CacheRead) + Output + Reasoning` from the
   faux `Usage`, `Basis = "provider_reported"` (budget §4: new tokens only).
6. **Stop reasons.** `tool_use`, `stop`, `length`, `refusal` map to the kernel `FinishReason`
   of the same name. `error` and `aborted` are failures (`ObserveModelFailure`), which the
   kernel does not decide yet (F3.3): the executor reports nothing for them and the attempt
   stays `Requesting`. Trace A never takes this path.

## Review Focus

1. **An observation that arrives before the dispatch reply** — the driver must not issue a
   second command for the same step. Pinned in Task 4 (`TestDriverActsOncePerCommittedState`).
2. **A duplicate commit notification** — idempotent: the same state yields the same command
   ID, so the store dedups. Pinned in Task 4.
3. **A payload that fails to seal** (vault locked mid-run) — nothing appended, the run waits;
   no plaintext in errors or logs. Pinned in Task 5 (`TestLockedVaultStopsTheSliceWithoutLeaking`).
4. **Tool arguments the model sends that `pure_read` rejects** — the check fails closed, no
   dispatch. Pinned in Task 3 (`TestInvalidToolArgsNeverDispatch`).
5. **Process exit right after the run finishes** — reopen shows 22 events and a finished run;
   nothing replays. Pinned in Task 5 (`TestTraceASurvivesReopenAndReplaysWithoutEffects`).

### Task 3: Model and tool executors

**Files:**
- Create: `internal/app/model_executor.go`, `internal/app/tool_executor.go` and tests
- Modify: `docs/adr/0001-package-layout.md` (`internal/app` row)

**Interfaces:**
- Consumes: `coordinator.Executor`, `Work`, `Observation`, `Payload`; `faux.Provider.Stream`;
  `pure_read.Tool.Prepare/Execute`; Task 2.
- Produces:

```go
type modelExecutor struct { provider *faux.Provider; ids ids.Generator; open payloadOpener }
type toolExecutor  struct { tool *pure_read.Tool; ids ids.Generator; open payloadOpener }
type payloadOpener interface { OpenPayload(ctx context.Context, sessionID, payloadID string) ([]byte, error) }
func (e *toolExecutor) check(ctx context.Context, sessionID string, plan *kernel.ToolCallPlannedEvent) (*kernel.ObserveToolCheckCommand, []coordinator.Payload, error)
```

  - Model: open the `context` payload named by the attempt's plan, build
    `modeladapter.Request`, stream; on the first event report `ObserveModelStream`; on `done`
    report `ObserveModelResponse` with `FinishReason` (scope decision 6), a `response` payload
    (assistant text), one `ToolCallPlannedEvent` per tool call with an `args` payload
    (`InputRef`), `EffectClass: pure_read`, `Usage` per scope decision 5.
  - Tool check: decode `pure_read.Args` from the `args` payload, `Prepare`; success →
    `ObserveToolCheck` with `ValidatedArgsRef` (the args payload), `GateObservation` (a
    `tool_gate` record); failure → no command, the error is returned (fail closed).
  - Tool execute: `Execute` the prepared plan, report `ObserveToolResult(succeeded)` with a
    `result` payload, plus `Facts.ModelPlan` for the next step whose `ContextRef` is a new
    `context` payload that includes this result (the kernel plans step 2 in the same batch).
