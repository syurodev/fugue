**Goal:** One logical command processor per session that is the only writer of its execution
stream: it admits queued runs, reserves worker capacity before a dispatch commit, hands work to
a worker exactly once after the commit is confirmed, reads back unknown commits by command ID,
fences stale workers, and re-arms durable timers.

**Architecture:** `internal/coordinator` (layer 3, ADR 0001 row already present) holds one
actor goroutine per session, started with `supervise.Go`. The actor owns a cached
`*kernel.State` per run, fills the facts it owns (envelope, token, incarnation, executor fence,
worker reservation), calls `kernel.Decide`, and appends through a `Store` port expressed in
kernel and codec types. `internal/app` adapts `*execstore.Store` to that port; the coordinator
never imports `execstore`.

**Tech Stack:** Go stdlib, `internal/kernel`, `internal/codec`, `internal/platform/{clock,ids,
supervise,errcode,redact}`, `go-cmp`, `goleak`. No new third-party module.

**Spec:** base-doc `content/projects/dev-kit/core-harness/` at commit `0ec4431`:
`event-storage-recovery` §2 (single writer, dispatch protocol), §3 (admission and fencing),
§7 (timers and restart); `architecture` §3 (one-step protocol), §6 (concurrency). Repository
authority: ADR 0001 (§3 rule 4: ports in kernel types, wired in `app`; §5: `exec_timers` owned
by `execstore`, phase F2.6), roadmap F2.6, `docs/quality-gates.md`.

## Global Constraints

- Only the session coordinator calls `Store.Append`; workers, the timer scheduler and callers
  send commands or observations to the actor and never touch SQL.
- Reserve a worker slot **before** the dispatch transaction; no slot means wait locally, with
  no `DispatchStarted` and no cancellation event.
- Hand off only after the commit is confirmed, exactly once per incarnation; never re-enqueue a
  `dispatching` intent, including after restart.
- Unknown commit: read back by the same command ID before any next step; while unresolved,
  stop dispatching and keep the slot; never mint a new command ID to retry.
- Failed commit or stop before dispatch returns the slot; the slot is memory only, never a
  persisted claim.
- No transaction, actor lock or mutex is held while waiting for a model, tool, user or worker
  slot; waiting for capacity never blocks other commands of the session.
- `kernel` stays pure; time comes from `clock.Clock`, IDs from `ids.Generator`; every goroutine
  starts through `supervise.Go` with a name and stop path; `context.Context` is never stored.
- Errors are `errcode` values declared in `internal/coordinator/errors.go` and listed in
  `docs/error-codes.md` (`TestErrorCodesPublished`).
- Coverage of `internal/coordinator` ≥ 90 %; non-test files ≤ 500 lines, test files ≤ 800;
  tests run with `-race -shuffle=on`, use the fake clock, and `TestMain` calls
  `goleak.VerifyTestMain`.
- Each PR stays under roughly 600 changed lines excluding tests and testdata; stop and consult
  the user before exceeding it.

## Scope decisions made by this plan

These follow from the spec and existing code; the reviewer may reject them.

1. **Unknown-commit classification lives in the adapter.** `execstore.Append` returns typed
   errors for definite rejections (`ErrStaleFence`, `ErrStaleRevision`, `ErrReceiptConflict`,
   `ErrInvalidBatch`, `ErrCodecVersionMismatch`, `ErrUnknownVersion`, `ErrSessionPurging`,
   payload limit errors, `ErrProtectedInputUnavailable`). Any other error from `Append` — the
   lost acknowledgement in `TestCommitLostAcknowledgementCommitted` is one — is reported to the
   coordinator as `ErrCommitUnknown`.
2. **Executor fence = sequence of the `DispatchStarted` event.** It is unique and monotonic per
   run across restarts and needs no new counter or table.
3. **Minimal queue is in memory and per incarnation.** Runs accepted in this incarnation are
   admitted FIFO when `activeRunID` is empty. Runs left `Queued` by an earlier incarnation stay
   `Queued` (recovery table, `event-storage-recovery` §7): the durable queue is F5.4.
4. **An active run inherited from an earlier incarnation is not touched.** The coordinator
   reports `ErrRecoveryRequired` for it and dispatches nothing; `AcquireRunOwnership` and
   `RecoverRun` belong to F3.1.
5. **Facts split.** The coordinator fills `Envelope`, `OwnerIncarnation`, `ExecutorFence` and
   `WorkerReservationRef`. The trusted in-process caller (later F2.9/F2.10) supplies
   `ModelPlan`, `ToolPlans`, `ModelDispatch`, `BudgetReservationRef`,
   `DispatchAuthorizationRef`, `Usage` and `ContextRefs`. The coordinator does not decide what
   the next step is.

## Review Focus

1. **Host shutdown while a commit is unknown** — the work is never handed off and the slot
   dies with the host. Pinned in Task 3 (`TestShutdownDuringUnknownCommitNeverHandsOff`).
2. **A worker that panics or returns nothing after handoff** — the attempt stays
   `dispatching`, the slot stays held, nothing is retried. Pinned in Task 4
   (`TestWorkerPanicKeepsAttemptDispatchingAndSlotHeld`).
3. **The same observation reported twice** — appended once; the second gets the duplicate
   reply. Pinned in Task 4 (`TestDuplicateObservationAppendsOnce`).
4. **The caller gives up while its command is in the actor** — processing finishes; the caller
   context only bounds waiting for the reply. Pinned in Task 2
   (`TestCallerCancellationDoesNotAbortAcceptedCommand`).
5. **A timer already overdue at restart** — fires once with the current fence, not once per
   missed interval. Pinned in Task 8 (`TestOverdueTimerFiresOnceAfterRestart`).

### Task 3: Dispatch protocol and unknown-commit read-back

**Files:**
- Create: `internal/coordinator/{dispatch.go,commit.go,dispatch_test.go,commit_test.go}`

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces: no new exported names. Internal behaviour:
  - A request whose decision would dispatch (`PrepareDispatch` on a `Planned` model attempt or a
    `Ready` tool attempt) first calls `slots.reserve()`. No slot: the request is parked in a
    FIFO; the actor keeps serving other requests and retries parked ones on every `release`.
  - With a slot, `Facts.WorkerReservationRef = ref` and `Facts.ExecutorFence =
    Envelope.Sequence` (scope decision 2), then `Decide`, then `Append`.
  - Definite rejection or `Decide` rejection → `release(ref)`.
  - Commit confirmed → `slots.handoff(ref, Work{...})` exactly once.
  - `ErrCommitUnknown` → `ResolveCommit(CommandID)`. `committed` → evolve with the batch and
    hand off; `not_committed` → release and re-run the same `Transition` (same command ID)
    when it is next scheduled; `unavailable` → the session enters `halted`, keeps the slot,
    rejects new dispatches with `ErrCommitUnresolved`, and retries `ResolveCommit` with the
    same ID after 1 s, 2 s, 4 s … capped at 30 s on the injected clock.
  - A worker pool of `WorkerCapacity` goroutines (`supervise.Go`, name
    `coordinator.worker`) reads the handoff channel and calls `Executor.Execute`.
