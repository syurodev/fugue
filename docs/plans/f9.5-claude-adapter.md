# F9.5 implementation plan (Claude adapter, stage A)

Implement the settled `vendor-runtime §5.1, §6, §8, §9, §12, §13` and `transcript §4` contract
for the Claude Code CLI: the vendor domain port, the Claude probe with a pinned version range,
the stream-json normalizer into transcript items, the slash command list, and `rate_limit_event`
as quota data. Evidence: VR-E01, TR-E01 (Claude), VR-E08 (roadmap F9.5).

## Layout note (ADR 0002 amendment, Q-37)

The Go toolchain does not descend into directories named `vendor` when expanding
`...` patterns (`go help packages`), so a package at `internal/vendor/claude` is
invisible to every wildcard-driven gate — `go list ./...` behind the arch tests,
lint, coverage, deadcode, fuzz discovery and the vendor-credential scan. The
adapter therefore lives at `internal/vendoradapter/claude` (parallel to
`internal/modeladapter`), the port stays at `internal/vendor`, and ADR 0002's
three adapter rows carry the new paths in a separate commit that needs the
owner's `gate-change-approved` label (roadmap Q-37).

`message_delta`, `message_stop`), one `rate_limit_event` with `unifiedWindows.five_hour` and

### Redaction (applied before commit; rules recorded for re-recording)

1. Every UUID (session id, event `uuid`, `hook_id`) → `uuid-NNNN` by order of first appearance
   (same original id always maps to the same placeholder, so tool_use ↔ tool_result matching
   stays verifiable).
2. `msg_…`/`req_…`/`toolu_…` ids (≥10 chars after the prefix; plugin slash names like
   `msg_lifecycle_v1` are not ids and stay) → `msg-NNNN`/`req-NNNN`/`toolu-NNNN`.
3. The recording directory path → `/home/REDACTED/claude-fixture` (in `cwd`, tool inputs,
   permission messages).
4. Thinking `signature` values → `REDACTED_SIGNATURE`; `signature_delta` `partial_json`
   fragments (long pure-base64 values only) → `REDACTED`.
5. `init.tools` collapsed to a fixed representative list (the recorded inventory is the owner's
   machine-specific MCP set; the field carries no fixture meaning). `slash_commands` and
   `terminal_slash_commands` stay as recorded — they are the vendor's own published lists and the
   input of the slash-list feature.
6. Verified clean before commit: old session id, emails, `sk-`/`gh*_`/`AKIA` tokens, real UUIDs,
   the recording path, signature blobs — all absent.

`testdata/fixtures/RECORDING.md` repeats this so the fixture can be re-recorded.

## API

`internal/vendor` (port, `vendor-runtime §6`): `Adapter` (`Probe`, `Start`), `Session`
(`Send`/`Interrupt`/`Steer`/`Resolve`/`Close`), `Probe` report (version, tested-range verdict,
login state, capability), `AccountHome`, `StartSpec`, `Input`, `TurnRef`, `ApprovalRef`,
`Decision`, `CloseReason`, `Capability`, `ErrUnsupported`, `ErrFugueCommand`.
`ValidateInput` enforces the composer rule of `vendor-runtime §9`: a prompt beginning with
`/fugue:` never reaches a vendor (typed `ErrFugueCommand`); `Session.Send` (F9.5b) calls it.

`internal/vendoradapter/claude`:

- `CheckedRange` 2.1.319–2.1.319 (only what the spike and this fixture verified, VR-08); any
  version outside still runs but `Probe`/`Init` report the untested-version warning.
- `Probe(ctx, home, env)` runs `claude --version` once through the §8 env filter
  (`process.FilterEnv`; `CLAUDE_CONFIG_DIR` when the home overrides it), parses the version and
  never touches vendor credential files (VR-03/E09; the arch scan already covers the new package).
  Login state: the CLI does not report it without a turn; the report says unknown until F9.10.
- `Normalizer`: pure, per session. `BeginTurn(turnID)` before each Send; `Normalize(line)`
  returns one `Observation`: records, updates (before/after pairs), the streaming partial
  (`stream_event` deltas as data for the actor's delta path), `Init` (version, model, permission
  mode, slash commands), `TurnEnd` (outcome, failure code, usage, `credential_expires_at`), and
  the full `rate_limit_event` window data for the future quota owner (F9.10). Item identity:
  tool_use id for tool calls (and the subagent/plan items keyed to it), message id plus a
  per-message block counter for text/thinking. Revisions: records at 0, each update +1.
- Mapping (transcript §4): assistant `text`/`thinking` → `assistant_message`/`reasoning`;
  `tool_use` → `tool_call` (pending), `TodoWrite` → `plan` (whole-list update per call),
  `Task` → `subagent`; `user` `tool_result` → `tool_call` update (succeeded, or failed on
  `is_error`); `system/permission_denied` → `tool_call` denied (recorded from the real CLI; the
  denial keeps its status when the error tool result follows); `Edit`/`Write`/`MultiEdit`
  succeeded → `file_change` with a diff computed from the tool input (hunk positions are
  placeholders — the file content is not in the event); `result` → turn end + `usage`;
  `rate_limit_event` → one `quota` item per window (account empty until F9.10); every event the
  normalizer does not map — `system/status`, `hook_started`, `hook_response`, `thinking_tokens`
  and anything unknown — becomes `notice(unsupported_event)` with the raw event reference
  (TR-06, VR-08), never dropped. Nested events (`parent_tool_use_id` set) are counted in the
  observation and not itemized in F9.5a; enriching the `subagent` item is F9.5b/F9.9 work.
- Slash list: `init.slash_commands` minus `init.terminal_slash_commands`, vendor order kept.
