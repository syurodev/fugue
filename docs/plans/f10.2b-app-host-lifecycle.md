# F10.2b App Host Lifecycle Implementation Plan

**Goal:** Start and connect a trusted local host, manage its app and background leases, and display version and startup failures.

**Architecture:** The UI keeps all application operations behind the public client and Host API. Host discovery and the connected peer must both be authenticated before use; the existing server-side credential check does not authenticate the server to the client. A detached host started by the app receives a fixed 10-second grace, and a single background app process holds the background lease after its window closes.

**Design:** desktop-app DA-01, DA-07 and DA-E08; cli §2.1–2.3; roadmap Q-25 and Q-36–Q-38.

## Constraints

- Foreground `fugue serve` keeps its zero idle grace; no signal-based upgrade shutdown.
- Startup waits at most 10 seconds using an injected clock; simultaneous launches converge on the lock winner.
- Use only a sibling `fugue` next to the resolved app executable, with no PATH fallback. Fail closed for unsafe ownership or write permissions and on unsupported platforms.
- The data and log directories are private, the log is private and bounded, and no secret is passed through arguments or environment.
- Authenticate discovery and connected socket ownership, permissions and peer credentials before Hello. Do not assume a server-side client check authenticates the server.
- Background mode is opt-in, one background lease process per data directory; close the lease explicitly when background mode is disabled.
- Defer the close confirmation for active sessions to F9.9/F10.5 because status lacks activity counts.
- Keep implementation at approximately 1,000 gross non-test lines; if it exceeds the ceiling, split the static font work into its own earlier PR.

## Tasks

1. **Trusted startup and grace.** Add the opt-in fixed idle-grace flag to `cmd/fugue`; test manual and app-started hosts independently. In `pkg/client` make discovery and dial validate private paths and server peer credentials with Linux/macOS implementations and Windows fail-closed stubs. In `ui/internal/hostconn`, verify the executable, create private bounded host logging, spawn and reap the detached child, and wait for authenticated readiness. Test unsafe paths, timeout, and competing starts using a real host where necessary.
2. **Leases, versions and window.** Extend `pkg/client` to expose client counts and Shutdown. Add lifecycle state to the UI, persist the Q-37 setting, coordinate a single background owner via a private local control endpoint, and supply an explicit stop action. Test lease transitions, restart on host loss, shutdown safety, version messages and the exact busy message. Place the F9.9/F10.5 TODO at the final-window close path.
3. **Fonts.** Replace variable fonts with licensed static faces and map each weight and style. Test measured bold and regular advances for both families.
4. **Verification and delivery.** Run focused tests, the core and UI gates and `go tool task check`; check UI CI on Ubuntu and macOS. Record actual test names and the deferred close confirmation in the roadmap. Measure gross lines per file; split fonts before opening the lifecycle PR if the limit is exceeded.

## Review focus

- Host discovery is attacker-controlled or swapped: fail closed and do not send Hello to an unauthenticated peer.
- Two launches race and the child exits before readiness: reap children and connect to the winner without treating a stale file as success.
- Background mode is toggled or the owner crashes: release or recover the single-owner lock without killing a host.
- Version incompatibility or other clients exist: do not restart or shut down an occupied host; never send signals.
- Logging or the data directory is unsafe or full: fail closed without exposing protected content or writing outside the private directory.
