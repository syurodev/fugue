# F5.3a — Interaction service for stage A implementation plan

Status: **working plan**, written 2026-11-09 against `main` at `bc9d083`. One branch, `feat/f5.3a-interaction-service`, one PR.

**Goal:** implement stage A interaction service in Fugue:
1. Proto `fugue.interaction.v1`:
   - `ListPending`: returns snapshot of pending requests of current incarnation + sequence of the `interaction` topic.
   - `Answer`: records user decision (`command_id`, `incarnation`, `request_id`, `outcome`, `option_id?`, `text?`, `answers[]?`).
2. View of a request (`PendingRequest`): `request_id`, `incarnation`, `session_id`, `tool`, `kind`, `risk`, `env_tag`, `summary` (representing summary/prompt), `offered_outcomes`, `options`, `grant_scope_label`. No extra fields outside this list.
3. Durable topic `interaction`:
   - Emits `interaction.requested` and `interaction.resolved`.
   - Event `resolved` carries ONLY outcome metadata, never request content (summary, prompt, answer text, notes/messages).
   - Snapshot and catch-up consistent with `ListPending`, no gap.
4. Public error codes: `interaction.not_found`, `interaction.already_answered`, `interaction.stale_incarnation`, `interaction.option_not_offered`, `interaction.text_too_large` in `internal/platform/errcode/errcode.go` and `docs/error-codes.md`. (`SetSessionPolicy` deferred to F9.9).
5. Deduplication by `command_id`: same `command_id` returns the identical previous result. Cache is bounded to 1024 entries with LRU/FIFO eviction and TTL to prevent unbounded memory growth.

## Architecture & Layering (ADR 0001 / ADR 0002)

1. **Layer 1 (`internal/interaction`):**
   - In-memory request owner per host incarnation.
   - Already provides `Ensure`, `Pending`, `Answer`, `TakeRelayed`, limits of §9, and audit events.
   - Augmented to carry `Risk` and `GrantScopeLabel` on `Spec` and `Ticket` so the request view can present them without leaking unapproved grants or extra fields.
2. **Layer 4 (`internal/app`):**
   - Application composition and services.
   - Implements `DurableTopic` for `interaction`:
     - Tracks committed interaction events with monotonically increasing sequence for the current incarnation.
     - `Snapshot(ctx)` returns current pending requests as snapshot state along with the current sequence under a mutex lock, guaranteeing snapshot-then-stream consistency without gaps.
     - `Since(ctx, seq)` returns all events strictly newer than `seq`.
   - `Backend` interface gains:
     - `ListPendingInteractions(ctx context.Context, principal string) ([]PendingInteractionView, EventSeq, error)`
     - `AnswerInteraction(ctx context.Context, cmd AnswerInteractionCommand) (AnswerInteractionResult, error)`
   - Command deduplication cache:
     - Maintains in-memory cache mapping `command_id` -> `AnswerInteractionResult` with a bound of 1024 entries and 10-minute TTL.
   - Authentication check:
     - Verifies caller principal is `local` (`tui`, `cli`, `app`, `app-background`).
     - Principal `session` (or unknown principal) is rejected typed with `permission_denied`.
     - Origin is taken from the authenticated principal, never from request fields.
3. **Layer 5 (`internal/hostapi`):**
   - `interaction_handler.go`: Connect handler for `fugue.interaction.v1.InteractionService`.
   - Maps proto `ListPendingRequest`/`AnswerRequest` to domain commands and maps domain results/errors to Connect responses.
   - Enforces transport-level payload size checks (§9) before allocation or copying.
   - Mounted onto server mux in `Server.Start`.
4. **Protobuf & Connect (`proto/fugue/interaction/v1` & `pkg/pb`):**
   - `interaction.proto`: defines `InteractionService`, `ListPendingRequest`, `ListPendingResponse`, `PendingRequest`, `Option`, `QuestionAnswer`, `AnswerRequest`, `AnswerResponse`.
   - Generated using `go tool buf generate proto --template proto/buf.gen.yaml`.

## Request View (`PendingRequest`)
Exact 11 fields:
1. `request_id`: unique ID of the request
2. `incarnation`: host incarnation ID
3. `session_id`: session ID
4. `tool`: tool name
5. `kind`: request kind (`confirm`, `select`, `question`)
6. `risk`: tool risk (`read`, `write`, `destructive`, `external`)
7. `env_tag`: target environment tag (`dev`, `prod`, etc.)
8. `summary`: text shown to user (summary for confirm/select, prompt for question)
9. `offered_outcomes`: outcomes offered for confirm (`allowed_once`, `allowed_session`, `denied`, etc.)
10. `options`: selectable choices for select or question
11. `grant_scope_label`: human-readable label for "allow for whole session" grant scope

No fields outside this list.

## Durable Topic `interaction`
- Topic name: `"interaction"`
- Events emitted:
  - `interaction.requested`: emitted when a request is opened; payload contains the pending request view.
  - `interaction.resolved`: emitted when a request is answered, cancelled, expired, or unavailable; payload contains ONLY `{"request_id": "...", "outcome": "..."}`. NEVER contains summary, prompt, answer text, or notes.
- Snapshot: atomic capture of all currently pending requests and the topic sequence.
- Catch-up: `Since(seq)` returns all events with `Seq > seq`.
- Consistent with `ListPending`: both read from the same state and sequence under lock.

## Public Error Codes
Added to `internal/platform/errcode/errcode.go` and `docs/error-codes.md`:
- `interaction.not_found`: The interaction request does not exist or has expired/been taken.
- `interaction.already_answered`: The interaction request has already been answered.
- `interaction.stale_incarnation`: The interaction request belongs to a previous host incarnation.
- `interaction.option_not_offered`: The selected option or outcome was not among the offered choices.
- `interaction.text_too_large`: The answer text or deny note exceeds size limits.

## Security Controls
- **Principal check**: Only `local` principals are permitted to call `Answer`, `ListPending`, or subscribe to topic `interaction`. Principal `session` (vendor runtime token) is typed rejected (`permission_denied`) in all three.
- **Size limits (§9)**:
  - Summary <= 2 KiB
  - Prompt <= 8 KiB
  - Answer <= 16 KiB
  - Note <= 4 KiB
  - Options <= 20
  Checked before allocation; oversized input rejected with `interaction.text_too_large` or `invalid_argument`.
- **Relayed requests**: Vendor relayed requests never produce session grants. An `Answer` selecting `allowed_session` on a relayed request is rejected with `interaction.option_not_offered`.
- **Vault locked**: Fail closed (I-E06). When vault is locked, answers other than denial are rejected (`failed_precondition`), preserving I-E06.
- **Content scrubbing (I-E08)**: Audit, logs, error messages, and `resolved` events NEVER contain summary, prompt, answer, or notes. String-scanning test verifies.
- **Race conditions**: Concurrent answers on the same request resolve exactly once; winner succeeds, second client gets `interaction.already_answered`. Tested under `-race`.
